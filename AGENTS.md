# Постоянные правила работы

- Не выполнять `git commit` без явного разрешения пользователя.
- Агент может предложить подходящий момент для коммита и текст сообщения, но должен дождаться подтверждения.
- Не выполнять `git push` без прямой команды пользователя.
- Никогда не выполнять force push.
- Не изменять историю Git без прямого разрешения.
- Все коммиты должны идти только от Git-пользователя пользователя. Не добавлять `Co-authored-by`, Codex, OpenAI, `Generated-by` или другие упоминания ИИ/агента в автора коммита, текст коммита, trailers, PR-текст или код.
- Не менять глобальную Git-конфигурацию. Использовать существующую Git identity пользователя. Если identity не настроена — сообщить, а не придумывать имя или email.
- Сообщения коммитов писать только по-русски, нормальным описанием результата в прошедшем времени, например: «Добавлена базовая структура backend».
- Делать небольшие логичные коммиты, но только после подтверждения пользователя.

## Экономия времени и токенов

- Сначала смотреть только необходимые файлы.
- Не выводить без необходимости большие логи, lock-файлы и содержимое всего проекта.
- Использовать короткие `git status` и `git diff`, когда этого достаточно.
- Не запускать повторно команды, результат которых уже известен и актуален.
- После изменения сначала запускать тесты затронутого модуля.
- Не запускать полный набор тестов после каждого мелкого изменения.
- Полные lint, typecheck, test и build запускать перед предлагаемым коммитом или при изменении общей архитектуры.
- Не устанавливать зависимость, если задача нормально решается уже установленными средствами.
- Перед добавлением зависимости проверять официальную документацию и необходимость зависимости.

## Безопасность

- Секреты никогда не помещать в Git.
- Настоящий `.env` должен быть в `.gitignore`; в Git хранить только `.env.example` без рабочих значений.
- Не логировать `MAX_BOT_TOKEN`, `DATABASE_URL`, пароли MySQL, `Authorization`, `Cookie` и `X-Max-Init-Data`.
- Перед потенциально разрушающими командами, включая удаление данных, `prisma migrate reset`, `docker compose down -v` и `git reset --hard`, остановиться и запросить разрешение.
